NSDEBase.AbstractInitialValueProblem — Type

An abstract type for initial-value problems.

A custom subtype used for chunked or moving-window solves must expose mutable rhs, u0 and tspan fields and implement remake(problem; u0, tspan). The remade problem must keep the supplied floating-point state buffer: chunk updates write into it. Solvers also need compatible initialize_cache, initialize_solution and solve! methods for the custom problem type.

NSDEBase.InitialValueProblem — Type
InitialValueProblem <: AbstractInitialValueProblem

A composite type for an initial-value problem. Time endpoints are promoted to a common floating-point type; integer and rational states are converted to floating point. Already-floating state vectors (including complex states) retain their storage. The solver time grid uses the resulting problem time type.

NSDEBase.LinearRightHandSide — Method
(rhs::LinearRightHandSide)(u, t)
(rhs::LinearRightHandSide)(du, u, t)
(rhs::LinearRightHandSide)(du, v, u, t)

returns the derivative du from the solution u and time t. The 3-argument in-place form allocates a temporary when a forcing term g is present. For a derived g(t), the dense output buffer has the operator's element type. Use a complex state in rhs(u, t) when a real operator has complex forcing. The 4-argument form takes caller-owned scratch v (same shape as du) instead and is allocation-free. Hot loops should use the 4-argument form.

NSDEBase.NonlinearRightHandSide — Type
NonlinearRightHandSide <: AbstractRightHandSide

A composite type for the right-hand side of an InitialValueProblem in the generic form $f(u, t)$.

Constructors

NonlinearRightHandSide(f, f!, Df, Df!)
NonlinearRightHandSide(f!_or_f; iscomplex=false, inplace=nothing)
RightHandSide(args...; kwargs...)
RHS(args...; kwargs...)

Arguments

  • f::Function : $f$, the right-hand side function
  • f!::Function : $f$ but in-place
  • Df::Function : $\mathcal{D}f$, the Jacobian of $f$ with respect to $u$
  • Df!::Function : $\mathcal{D}f$ but in-place

When only f!_or_f is given, the missing form is derived from it and the Jacobian is filled in automatically: ForwardDiff for real problems, and a finite-difference Wirtinger derivative (via FiniteDifferences) when iscomplex = true. Function-based IVP constructors infer this from complex initial data. This computes ∂f/∂u; implicit complex solves require a holomorphic RHS. For non-holomorphic equations, split real and imaginary parts explicitly. Optional arguments are interpreted by the shortest supported signature; use inplace=true or inplace=false to resolve ambiguity.

NSDEBase.SolverFailure — Type
SolverFailure <: Exception

An abstract type for numerical failures: a solver could not produce a usable step (for example, Newton or adaptive-step failure). Custom solvers may subtype it to request numerical failure handling in Parareal and MoWi. Programming and configuration errors must use their ordinary exception types instead.

NSDEBase.SplitRightHandSide — Method
(rhs::SplitRightHandSide)(u, t)
(rhs::SplitRightHandSide)(du, u, t)
(rhs::SplitRightHandSide)(du, v, u, t)

returns the derivative du from the solution u and time t. The 3-argument in-place form allocates a temporary; the 4-argument form takes caller-owned scratch v (same shape as du) instead and is allocation-free. v is used first as scratch for fₛ and then to hold fₙₛ(u, t), so a single buffer covers the whole evaluation. Hot loops should use the 4-argument form.

NSDEBase.chunk_solver — Method
chunk_solver(solver, duration)

prepares a solver for a chunk of nominal duration. Solver packages may specialise it to share a fixed schedule across translated chunks. The fallback copies the solver, so run-local mutable state is never shared with its caller.

NSDEBase.remake — Method
remake(problem; u0=problem.u0, tspan=problem.tspan)

builds a problem with the same right-hand side and selected new initial data. Time-span endpoints are promoted to a common numeric type. A supplied floating-point state is not copied; other numeric states are converted. Use copy(u0) for independent storage. Other subtypes of AbstractInitialValueProblem must implement their own method; the fallback throws an ArgumentError.

source
NSDEBase.solve — Function
solve(problem, solver; kwargs...) :: AbstractSolution

computes the solution of problem using solver, allocating a fresh cache and solution. Solver packages extend this function; hot loops should prefer the cache-reusing solve!.
